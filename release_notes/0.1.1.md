# ka-telemetry 0.1.1

A fix release. Everything in [0.1.0](0.1.0.md) still holds.

## Fixed

- The receiver starts listening at once. It no longer looks up the machine's own name when it binds its port; on a machine whose name lookups are slow, that lookup held its start for tens of seconds.
- On Python 3.11, the per-agent report and its compare totals add costs with correct rounding, so the same records give the same figures on every supported Python. Python 3.12 changed how Python adds fractions, and on 3.11 the same total could end in ...0000001.
- On Python 3.11 and 3.12, the steps report finds the same workflow runs it finds on later Pythons: also when a run's `journal.jsonl` is a link that leads nowhere, or a directory on the way can be entered but not listed, or listed but not entered.

## Releasing

- A version is published to PyPI only after the tests pass on Python 3.11, 3.12, 3.13 and 3.14, on Linux and macOS, and the release check holds, all on the exact commit the version's tag names. The tag must name the version `pyproject.toml` declares, and the package is built from that same commit.

## Tests

- The tests run on every Python ka-telemetry declares, 3.11 through 3.14, not only the oldest and the newest.
- The tests pass on GitHub's Linux and macOS runners: the two release-check tests that try a pip install read no site-wide pip configuration, as the release check itself does, and two tests that depend on the machine allow for a slow resolver and for a Python that cannot be copied privately.
